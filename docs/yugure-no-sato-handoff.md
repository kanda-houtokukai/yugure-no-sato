
- 出力は `.screenshots/`（gitignore 済み）。`<日時>-<視点>.png` と `report-<日時>.json`。verify は各スクショの sha256 を出す。
- **撮った絵は必ず自分で Read して目視判定する。** レポートの ○ だけで終わらせない
  （輝度と分散が正常でも、絵が意図と違うことはある）。
- ゴールデンビューは**バイト単位で再現する**（実測で確認済み）。
  スクショの sha256 が前回と変われば、描画が変わったということ。回帰検出に使える。各段階の値は経緯アーカイブに記録。
- URL パラメータで視点を上書きできる: `eye=x,z,above` `yaw` `pitch` `fov` `t` `sunAz` `sunEl` `exposure` `dbg`。
- **シェーダを変えた直後の 1 回目は GPU 時間が 30〜40ms と出ることがある**（コンパイル直後の一過性）。
  2 回目以降の値で判断する。

## 生きている注意事項

- ⚠️ **素材ファイルを1つでも入れたら実験として失格。** テクスチャ・3Dモデル・画像・音源すべて。
  判定は `git ls-files` にそれらの拡張子が現れないこと。
- ⚠️ **描画ライブラリ禁止。** `dependencies` は原則空。`devDependencies` は vite / typescript / 型定義と、
  自己修正ループに必要な最小限のみ。増やしたくなったら**停止して報告**。
- ⚠️ **仕様に無い選択を迫られたら、実装せず報告して停止する。** 勝手に決めない。
- ⚠️ **区切りごとに push して SHA を報告する。** 設計側は raw で裏取りするため、
  push 済みでないものは存在しないものとして扱われる。
- ⚠️ **public を維持する。** private 化すると設計側の裏取り手段が消える。
- ✅ **解消済み（2026-09-06）**: Chrome 152 安定版で WebGPU が取れることを機械確認した。
  **Canary は不要**（下記「WebGPU 環境」）。
- ⚠️ **`npm install` はグローバル設定の deny で止まる**（`~/.claude/settings.json` の `Bash(npm install*)`）。
  これは意図的なガード。Code が勝手に外さず、**神田さんに自分のターミナルで実行してもらう運用**とする
  （2026-09-06 に本人が選択）。依存を足す必要が出たら、コマンドを提示して待つ。
- ⚠️ **`@types/node` を入れない。** devDependencies を vite / typescript / @webgpu/types の3点に保つため、
  `vite.config.ts` は `tsconfig.json` の型検査対象から外してある（`include: ["src"]`）。
  Vite は設定ファイルを実行時にトランスパイルするだけなので実害はないが、
  **`vite.config.ts` の型は機械保証の外**である点は把握しておくこと。

- ⚠️ **sink は本文の無い 204 を返してはいけない。** 書き込みが成功していても Chrome が
  `net::ERR_ABORTED` を出し、verify が偽の異常を報告する。必ず本文つきの 200 を返す。
- ⚠️ **favicon はファイルを置かず `<link rel="icon" href="data:,">` で要求ごと消す**（素材ゼロの原則）。
  無いと `/favicon.ico` の 404 が verify を汚す。
- ⚠️ **Playwright は `channel: 'chrome'` で実機の Chrome 安定版を起動する。** 同梱 Chromium は入れていない
  （`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` でインストール）。probe で実証した動作条件をそのまま引き継ぐため。
- ⚠️ **スクショは `window.__yugure.firstFrameDone` → `sceneDone` を待ってから撮る。**
  WebGPU の初期化は非同期で、待たずに撮ると真っ黒が写る。

- ⚠️ **数式（`world.wgsl`）は唯一の正本。TS に複製しない。** CPU が要る値は `runQuery`（compute）で読み戻す。
- ⚠️ **数式を画素ごとに複数回評価しない。** 3 回で GPU の占有率が崖を越え 30〜77ms（実測）。
  高さ・法線・日向・畦距離は起動時にテクスチャへ焼き、画素側は 1 タップで読む。
- ⚠️ **太陽を動かす運用にするなら、空 LUT・法線/日向/畦距離テクスチャの焼き直しが要る**（合計 ≈100ms）。
- ⚠️ **座標系は実地図の鏡像**（北を向くと東が左）。内部では一貫しており検証も通る。実地図と比べる用途が出るまで触らない。
- ⚠️ `float32-filterable` 機能に依存（r32float の線形補間）。この Mac では利用可。
- 📋 **未検証**: 実機 Chrome で 60fps が出るかは、GPU 時間 12ms から推定しているだけ。画面付き実行での実測は
  操作を入れるフェーズ3で行う。

## WebGPU 環境（確定・2026-09-06 実測）

`node tools/probe.mjs` による実測。**Chrome の起動条件4通りすべてで WebGPU が取れた。**

| 起動条件 | 結果 |
|---|---|
| headed（フラグなし） | ✅ |
| headed + `--enable-unsafe-webgpu` | ✅ |
| **`--headless=new`（フラグなし）** | ✅ |
| `--headless=new` + `--enable-unsafe-webgpu` + `--use-angle=metal` | ✅ |

- **特別な起動フラグは不要。** `--enable-unsafe-webgpu` も `--use-angle=metal` も要らない。
- **ヘッドレスでも WebGPU が動く。** パートAで想定していた「ヘッドレスでは動かない」懸念は外れた。
- アダプタ: `vendor: apple` / `architecture: metal-3` / subgroup サイズ 32 固定
- `preferredCanvasFormat: bgra8unorm`
- 主要な上限値: `maxBufferSize` **4,294,967,292**（約4GiB）／`maxStorageBufferBindingSize` 同値／
  `maxComputeWorkgroupSizeX,Y` 1024・`Z` 64／`maxComputeInvocationsPerWorkgroup` 1024／
  `maxComputeWorkgroupsPerDimension` 65,535／`maxComputeWorkgroupStorageSize` 32,768／
  `maxTextureDimension2D` 16,384／`maxStorageBuffersPerShaderStage` 10／`maxColorAttachments` 8
- 使える主な機能: `shader-f16`・`subgroups`（size-control 付き）・`timestamp-query`・`float32-filterable`・
  `float32-blendable`・`dual-source-blending`・`depth-clip-control`・`bgra8unorm-storage`・
  `primitive-index`・`clip-distances`
- 全文は `.screenshots/probe-attempts.json`（gitignore 済み）。再取得は `node tools/probe.mjs`。

## 2026-09-06 — フェーズ1: 大地と水と空（完了）

段階の順序は指示どおり 地形 → 空と光 → 水面 → あぜ道。各段階で verify を回し、絵を自分で読んでから次へ。

### 段階1: 地形（完了・commit 済み）

**[DECISION] リングメッシュの構成**（自分で決めた値と理由）
- 扇形 **512** 分割、最内半径 **0.5m**、最外半径 **16km**、隣接リングの半径比 **k = 1 + 2π/512 ≈ 1.01227**
  → リング **852** 本、頂点 **436,225**、三角形 **871,936**、**draw call 1 回**
- 理由: k をこの値にすると「リング間隔 = 扇形の弧長」となり、どの距離でも三角形がほぼ正三角形になる。
  近くは細かく遠くは粗い、が自動で成り立つ。512 は遠景の稜線の角分解能（0.7°≈16px）から決めた
- 頂点バッファなし。頂点シェーダが `vertex_index` から極座標を起こし、高さは数式（`world.wgsl`）
- リング中心はカメラ xz。カメラ相対で描くので 16km 先でも f32 の精度が足りる
- 深度は **逆 Z・無限遠**（depth32float, compare greater）
- 遠景の山並みは**同じリングの外周**で成立した（別手段への切り替えは不要）。
  山は盆地の縁からの超楕円距離 t で 3 層（t=6〜14 / 12〜24 / 22〜40。北側で約 1km / 2.4km / 4.2km〜7km）

**[DECISION] 正本は WGSL のみ**
- 高さ・区画・川・道の式は `src/shaders/world.wgsl` にだけある。TypeScript に複製しない。
- CPU が値を要るとき（視点の地面高さ、水面セルの形）は compute（`query.wgsl`）で正本を評価して読み戻す。
  「TS と WGSL の式が食い違う」事故をそもそも起こさない。

**[DECISION] 画素の法線は起動時に焼く高さテクスチャから取る**
- 数式を画素ごとに 3 回（高さ＋差分 2 回）評価すると **GPU 30〜77ms**。評価回数と時間が比例せず
  （1回 +3.5ms、2回 +3.2ms、3回 +19ms）、レジスタ圧で占有率が崖を越えたと判断。ループ化でも変わらず。
- 対策: 起動時に compute で **近・中・遠 3 段 × 2048² の r32float**（テクセル 0.2 / 1.6 / 12.8m、計 48MB）を
  焼き、画素の法線はそこから取る（近景は双三次補間で C1 連続に）。材質判定の数式評価は画素ごと 1 回のまま。
  焼く時間 **約 46ms（1 回きり）**。**GPU 8.2ms/フレーム**に収まった。
- `float32-filterable` 機能が要る（この Mac では利用可）。無い環境では双線形を自前で組む必要がある。
- 数式は依然として唯一の正本。テクスチャはそこから生成した派生物。
- 副産物: フェーズ2の稲（大量インスタンスの高さ参照）もこのテクスチャを引けば軽い。

**地形生成の方式**
- 谷座標 (u, v): u = x、v = z − riverZ(x)。川は 3 つの正弦の和で蛇行。
- 区画: (u, v) の格子（縦 26m × 横 17m）。線ごとに低周波ノイズでうねらせ、行ごとに縦線を確率 30% で抜いて
  区画を合併 → 不規則な四角形。行 0 は川の帯（半幅 6.5m）で区画にしない。
- 水面高さ: 谷底基準面を 0.12m 刻みに量子化 ＋ 区画ごとの ±2.5cm → 隣り合う区画で少しずつ違う。
- 畦: 線からの距離で盛り上げ（半幅 0.8m、基準面 +0.42m）。**足元（メッシュ間隔）より細い盛り上がりは
  鋸歯状に拾われる**ので、評価する足元の大きさに応じて幅を広げ高さを下げる（体積保存）。画素側は本来の幅。
- あぜ道: 縦線 0 に沿う主道（南の集落側 → 北の神社の丘）＋ 横線 4・−3 に沿う副道 2 本。基準面 +0.55 / +0.45。
- 盆地: 超楕円（北半幅 ≈175m、南 ≈130m、長さ ≈520m、縁はノイズ）。丘は t=0.95〜3.6 で 70m まで。

### 段階2: 空と光（完了・commit 済み）

**[DECISION] 大気は単一散乱モデル（Rayleigh + Mie + オゾン）＋ Rayleigh 限定の多重散乱近似**
- `atmosphere.wgsl`。惑星半径 6371km・大気 60km・Rayleigh 8km・Mie 1.2km。夏の靄として Mie を
  やや濃く（1.0e-5）、吸収性（散乱の 50%）にして直射を落とす。
- 単一散乱だけだと空が暗すぎ、直射：上向き面の空の放射照度 = **28:1**（実測。現実は 3〜6:1）。
  各点で等方に散る二次光を太陽透過率に比例して足す近似（MULTI_SCATTER=2.0）で **7:1** まで寄せた。
  **Mie にも掛けると天頂まで白く濁る**ので Rayleigh（青）に限る。
- 放射照度の実測値はレポートの `resolved.light` に出る（露出判断の材料）。

**[DECISION] 太陽は方位 275°（真西やや北）・仰角 3.5°。谷の出口を低くしてそこに沈める**
- 盆地を囲む丘 70m（≈600m 先で仰角 6.6°）や山は 3.5° の太陽を隠す。北向き・西向きどちらでも。
- 川が西へ抜ける切れ目（`outlet`: u < −320〜−620、|v| < 110〜260）で丘 ×0.3・山 ×0.15 にして、
  そこへ夕日を沈める。逆光の水面（段階3）と畦の長い影はこれで成り立つ。

**[DECISION] 空・法線・日向/日陰は起動時に焼く（太陽が固定だから）**
- 空: 正距円筒 512×256 rgba16float の LUT を 1 回焼く。空の描画・環境光・映り込みが参照。
  太陽の円盤だけ解析的に足す（透過率は reduce が出した直射から）。
- 環境光: LUT の cos 重み半球積分（reduce compute）。**4 方向サンプルの平均は不可**——
  西の 1 サンプルが太陽周りの輝きを拾い、地面全体が黄色に飽和した（実測）。
- 法線と日向/日陰: 高さテクスチャから段ごとに rgba16float 1 枚（r,g = 法線 xz、b = 太陽可視度）に焼く。
  画素側は 1 タップ。双三次法線 5.7ms・影の行進 5.3ms が消えて **GPU 11.3ms**。焼きは 47ms（1 回）。
  `rg16float` / `r8unorm` は storage 書き込み非対応（検証エラーで判明）。
- 太陽が動く運用にするなら、この 3 つの焼き直しが要る（数十 ms）。

**★教訓**

### 段階3: 田んぼと水面（完了・commit 済み）

**[DECISION] 水面メッシュは正本（WGSL）から compute で区画の形を読み戻して CPU が組む**
- `cellQuery`: 格子索引ごとに「合併の左端かつ田んぼ」なら水面高さと 9×3 の格子点（世界 xz）を返す。
  線は u↔v が互いに依存するので 3 回の不動点反復で交点を落ち着かせる。361 区画・12,452 三角形。
- 小川は `riverQuery`（中心線）から半幅 3.2m の帯（水面 2.6m より広く、土手の下に隠す）。
- 水面の縁は畦の中心線まで伸ばす。畦の頂（基準面 +0.42）は水面（基準面 ±0.2）より高いので隠れる。

**[DECISION] 遠くの畦は幾何でなく「焼いた畦距離」で保つ**
- 畦（幅 1.6m・高さ 0.4m）は遠くではメッシュ間隔（400m 先で 5m）より細く、幾何では表せない。
  足元に応じて広げる方式は上限 3 倍まで（それ以上は区画の内部まで持ち上がり、水面が地形に潜って
  **bird 視点で水が 1 画素も出なかった**。平均輝度が水なしと同一という数値で発覚）。
- 足元 1.5〜3m で畦・道の幾何は消し、代わりに焼いた rgba16float の a に「畦・道の中心線までの距離」を
  入れ、水面シェーダがその線上（< 0.6m）を discard する。どの距離でも区画の網目が残る。

**水面の見え方**
- 空 LUT の映り込み（Fresnel, F0=0.02）＋太陽の円盤の鏡像（畦の影の中では消える）＋濁った浅い水底
  （濡れた泥 0.12・深さ 0.12m の吸収・濁りの散乱）。上から見ると暗い鏡、かすめて見ると空と夕日。
- さざ波は正弦 4 波の和。**画素の足元（かすめる視線では奥行きに伸びる）より短い波は落とす**。
  落とさないと画素より細かい波がモアレになる（実測）。

**[DECISION] 太陽の映り込み位置の機械検証**（指示の落とし穴への対応）
- 平らな水面なら太陽の鏡像方向（sunDir の y を反転）に最も明るい点が出る。ページ側で予測画素と、
  地平線より下で最も明るい領域の重心を比べ、ずれ < 2° を要求。実測 **0.05°**。
- verify は水面視点をもう 1 枚、太陽方位 +8° で撮り直し、予測 Δx −98px に対し観測 Δx −89px を確認。
  「それらしい絵だが物理的に間違っている」状態を毎回機械で弾く。

**★注意（座標系）**: この世界は x=東・z=北・y=上と呼んでいるが、右手系ではこの並びは実地図の鏡像
（北を向くと東が左に見える。方位は左回りに増える）。太陽・視点・映り込みの計算はすべてこの系で
一貫しており、検証も通っている。**実地図と比べる用途が出たら x を反転する**。それまでは触らない。

# 台帳の維持規則

- 台帳は**毎セッションが起動時に読む**。肥大はコンテキストを毎回浪費する。
- **現在地サマリは常に 1〜2画面以内**に保つ。それ以外は経緯アーカイブへ。
- **版/フェーズの記録は直近 10 件まで。** 11 件目を足す前に、最も古い1件を
  `docs/yugure-no-sato-archive-YYYY-MM.md` へ**原文のまま**移してから追記する。
- **台帳が 3 万文字を超えたら**、まず記録の件数を数える:
  1. 規定数（10件）以内 → 規則は守られている。重い回が続いただけ。何もしない
  2. 規定数超過 → **超過分だけ**をアーカイブへ移す
- **チェックの引き金は「版/フェーズを追記するとき」**。追記の直前に必ず数える。誰かが気づくのを待たない。
- ⚠️ **要約・圧縮による削減は禁止**（アーカイブは原文保存が目的）。
- アーカイブは**月別**に分ける（`yugure-no-sato-archive-YYYY-MM.md`）。
- 移す前に、その中の**いまも効いている制約**（確定値・禁則・落とし穴）を
  「生きている注意事項」へ昇格させる。迷ったら残す側に倒す。
- 決定には `[DECISION]`、教訓には `★` を付け、後から検索できるようにする。
